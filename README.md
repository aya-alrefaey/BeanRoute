# ☕ BeanRoute — متجر بن إلكتروني (React Final Project)

متجر بن متخصص، كل منتج فيه بيتقدّم كـ "رحلة" من المزرعة لحد الكوب، مع خريطة تفاعلية توضح
مسار الشحن من بلد المنشأ لحد المحمصة في القاهرة.

## التقنيات المستخدمة
- **React 18** + **Vite** (بدل Create React App — أسرع في التشغيل والبناء)
- **React Router v6** للتنقل بين الصفحات
- **Bootstrap 5** + **Bootstrap Icons** للـ Grid والمكونات الأساسية
- **React-Leaflet** + **Leaflet** للخريطة التفاعلية (OpenStreetMap)
- **json-server** — API وهمي (Mock REST API) لتسجيل الدخول/الحساب، بيتصرف زي أي backend حقيقي (GET/POST) لكن من غير سيرفر فعلي أو قاعدة بيانات خارجية
- **Context API** لإدارة حالة السلة والمستخدم (Cart + Auth) بدون مكتبات خارجية زيادة
- **CSS مخصص** (`src/index.css`) فوق Bootstrap لهوية بصرية مميزة (نظام ألوان "باسبور رحلة")

## ⚠️ Auth شغّالة على API وهمي — مش آمنة للإنتاج

تسجيل الدخول والحساب الجديد بيتكلموا مع `json-server` على `http://localhost:3001` كأنه
REST API حقيقي (نفس شكل fetch/axios اللي هتستخدمه مع أي backend فعلي). ده مثالي للعرض
والتجربة، لكن خد بالك:

- الباسورد بيتخزن **نص عادي (plain text)** في `db.json` من غير أي تشفير
- مفيش JWT ولا Sessions حقيقية — الجلسة بتتحفظ في `localStorage` بس
- **البيانات بتضيع لو غيّرت الجهاز أو رفعت المشروع أونلاين** لأن `json-server` بيشتغل محليًا بس

في مشروع حقيقي/للتسليم النهائي، لازم تستبدل ده بـ backend فعلي بيعمل hashing للباسورد
(زي bcrypt) ويستخدم JWT.

## تشغيل المشروع محليًا

المشروع محتاج **سيرفرين شغالين مع بعض**: الفرونت اند (`Vite`) والـ API الوهمي (`json-server`).

### الطريقة الأسهل — أمر واحد يشغّل الاتنين مع بعض:
```bash
npm install
npm run dev:all
```
هيفتح الفرونت على `http://localhost:5173` والـ API على `http://localhost:3001` في نفس الوقت.

### أو لو عايز تشغّلهم في تيرمينالين منفصلين (أوضح للتشخيص):
```bash
# تيرمينال 1
npm run dev

# تيرمينال 2
npm run api
```

للبناء للإنتاج:
```bash
npm run build
npm run preview
```
> ملحوظة: `npm run preview` بيشغّل الفرونت بس — لازم `npm run api` يفضل شغال في تيرمينال تاني عشان تسجيل الدخول يشتغل.

```
src/
```

## الصفحات المتاحة

| الصفحة | الوصف |
|---|---|
| `/` | الرئيسية — Hero + مناشئ مختارة + خطوات الرحلة |
| `/products` | المتجر — بحث وفلترة (بالدولة، درجة التحميص، السعر) |
| `/products/:id` | تفاصيل المنتج — القصة + خريطة تفاعلية + تقييمات ومراجعات |
| `/cart` | السلة — تعديل الكمية، حذف، ملخص السعر |
| `/checkout` | الدفع — بيانات شحن، طرق دفع متعددة، كود خصم، بيسجّل الطلب فعليًا |
| `/orders` | تاريخ الطلبات (محتاج تسجيل دخول) |
| `/wishlist` | المفضلة — قائمة المنتجات المحفوظة |
| `/profile` | الملف الشخصي — تعديل الاسم/الموبايل/العنوان + بيانات دفع بصرية (محتاج تسجيل دخول) |
| `/login` `/register` | تسجيل الدخول / حساب جديد (بما فيها اختيار دور "بائع") |
| `/about` | قصة المتجر |
| `/admin` `/admin/users` `/admin/orders` `/admin/banners` | لوحة تحكم الأدمن (محتاج حساب دوره admin) |
| `/seller` | لوحة البائع — إدارة منتجاته الخاصة (محتاج حساب دوره seller) |

## 🔑 حسابات تجريبية جاهزة

| الدور | الإيميل | الباسورد |
|---|---|---|
| أدمن | `admin@beanroute.com` | `admin123` |

للبائع: سجّل حساب عادي من `/register` واختار "بائع (محمصة)" وقت التسجيل.

## الفيتشرز الجديدة

**المفضلة (Wishlist)** — زرار قلب على كل منتج (في الكارت وصفحة التفاصيل)، بيتحفظ في
`localStorage` فمش محتاج تسجيل دخول. صفحة `/wishlist` بتجمعهم كلهم مع إمكانية إضافة
للسلة أو إزالة من المفضلة مباشرة.

**تاريخ الطلبات (Order History)** — أي طلب بيتأكد من صفحة الدفع بيتسجّل فعليًا في
`db.json` تحت `orders` (لو المستخدم مسجّل دخوله، بيترابط بـ `userId` بتاعه). صفحة
`/orders` بتجيب طلبات المستخدم الحالي بس. الضيوف (Guest checkout) طلباتهم بتتسجل
برضه بس من غير `userId` فمش هتظهرلهم في الصفحة دي.

**التقييمات والمراجعات (Reviews & Ratings)** — في أسفل كل صفحة منتج، فيه متوسط
تقييم بالنجوم + قائمة كل المراجعات، وفورم لإضافة تقييم جديد (محتاج تسجيل دخول).
البيانات متخزنة في `db.json` تحت `reviews` ومرتبطة بـ `productId`.

**إدارة البروفايل (Profile Management)** — صفحة `/profile` بتسمح للمستخدم يعدّل
اسمه، رقم موبايله، عنوانه، ومدينته — والتعديلات بتتحفظ فعليًا في `db.json` عن طريق
`PATCH` request. فيه كمان قسم "بيانات الدفع" بصري بس (اسم حامل الكارت + رقم الكارت
منسّق) لغرض العرض في الديمو، من غير أي تخزين أو معالجة دفع فعلية. بيانات العنوان
والموبايل المحفوظة بتتعبّي تلقائيًا في صفحة الـ Checkout.

**لوحة تحكم الأدمن (Admin Panel)** — محمية بـ `ProtectedRoute` (بتتحقق إن
`user.role === 'admin'`)، وفيها 4 صفحات:
- **نظرة عامة (`/admin`)** — إحصائيات سريعة (عدد المستخدمين، الطلبات، الإيرادات، المنتجات)
- **المستخدمين (`/admin/users`)** — عرض كل المستخدمين، وحظر/إعادة تفعيل أي حساب
  (Soft delete عن طريق حقل `restricted` بدل الحذف الفعلي — الحساب المحظور مينفعش
  يسجّل دخول تاني، وده متحقق منه في `AuthContext`)
- **الطلبات (`/admin/orders`)** — عرض كل الطلبات وتغيير حالتها (قيد المعالجة → تم الشحن → تم التوصيل...)
- **محتوى الصفحة الرئيسية (`/admin/banners`)** — تعديل عنوان وعنوان فرعي البانر الرئيسي
  (متخزن في `db.json` تحت `banners`، محتاج ربطه فعليًا في `Home.jsx` لو عايز يبان تلقائيًا)

**لوحة البائع (Seller Dashboard)** — صفحة `/seller` محمية لأصحاب `role === 'seller'` بس،
فيها فورم لإضافة منتج جديد (اسم، منشأ، سعر، مخزون، صورة، وصف) وقائمة بمنتجات البائع
الحالي مع تعديل وحذف (CRUD كامل عن طريق `sellerProducts` collection في `db.json`).
ملحوظة: منتجات البائعين دي منفصلة عن كتالوج البن الأساسي في `src/data/products.js`
(اللي بيظهر في `/products`) — دمجهم مع بعض محتاج شغل إضافي حسب متطلبات المشروع.

**بوابة دفع Stripe (Test Mode)** — في صفحة الـ Checkout، لما تختار "بطاقة ائتمان" بيظهر
فورم شبيه بـ Stripe Elements (`src/components/StripeCardForm.jsx`) بيتحقق من رقم الكارت
(Luhn algorithm)، تاريخ الانتهاء، والـ CVC، وفيه زرار "استخدم كارت تجريبي" بيعبّي كارت
الاختبار الرسمي من Stripe (4242 4242 4242 4242). **ده محاكاة بس ومفيش اتصال حقيقي بـ
Stripe** — لدفع حقيقي فعلي لازم `@stripe/stripe-js` + مفتاح Publishable Key حقيقي +
backend بينشئ PaymentIntent (السر مينفعش يتحط في الفرونت اند لأسباب أمان).

## ملاحظات مهمة قبل التسليم

هذا **الواجهة الأمامية (Frontend)** فقط، جاهزة ومصممة بالكامل. عشان تكمل المتطلبات الكاملة
للمشروع محتاج تضيف:

- **Backend حقيقي** بيعمل hashing للباسورد ويستخدم JWT بدل json-server (اللي بيتخزن الباسورد نص عادي)
- **Stripe حقيقي** (مش Test Mode بس) — يحتاج حساب Stripe فعلي وbackend لعمل PaymentIntent
- **تأكيد بالإيميل** عند التسجيل، وإشعارات إيميل لتحديثات الطلب
- **دمج منتجات البائعين** مع كتالوج المنتجات الأساسي بدل ما يفضلوا منفصلين

المنتجات والصور الحالية بيانات تجريبية (Mock Data) في `src/data/products.js` — استبدلها ببيانات
حقيقية من الـ API بتاعك.
